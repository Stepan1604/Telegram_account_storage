# 🏛 Telegram Account Storage

Бот-хранилище Telegram-аккаунтов с шифрованием сессий, автоочисткой,
покупкой через LZT Market и экспортом в CSV.

## 📋 Возможности

### 📦 Хранилище аккаунтов
- Добавление аккаунтов через бота (номер → код → 2FA)
- Покупка номеров на **LZT Market** (одиночная / оптовая / импорт)
- Просмотр всех аккаунтов с пагинацией и группировкой по странам
- Избранное (избранные всегда сверху)
- Пользовательские названия (по умолчанию — номер)
- Смена статуса вручную (очищен / ожидает / мёртвый)

### 🔐 Безопасность
- **Шифрование session_string** через Fernet (AES-128 CBC + HMAC)
- Прозрачное шифрование на уровне SQLAlchemy (`EncryptedText`)
- Ключ хранится отдельно от БД (`secret.key`)
- Автоматическая установка **2FA-пароля** на новые аккаунты
- Проверка прав администратора через middleware + декоратор

### 🧹 Очистка и обслуживание
- **ResetAuthorizations** — завершение всех чужих сессий
- **Выход из групп и каналов** (`LeaveChannelRequest`)
- **Удаление всех чатов** (`DeleteChatUserRequest`, `DeleteHistoryRequest`)
- Автоочистка через 24 часа после добавления
- Прогрев всех сессий при старте бота
- Обнаружение **замороженных** аккаунтов (`FrozenMethodInvalidError`)

### 🔍 Проверка аккаунтов — три состояния

Кнопка **«🔍 ПРОВЕРКА АККАУНТОВ»** различает три исхода для каждого
аккаунта:

| Состояние | Что значит | Что происходит со статусом |
|---|---|---|
| ✅ **Живой** | `is_user_authorized()` + `get_me()` прошли | `status = "uncleaned"` (если был `dead` — возвращается в работу) |
| ❌ **Мёртвый** | Бан, деактивация, аннулированный ключ, невалидная сессия | `status = "dead"` |
| ❔ **Не проверился** | Timeout, FloodWait, `TypeNotFoundError` (устаревший Telethon), любая техническая ошибка | **статус НЕ меняется**, растёт только `health_fail_count` |

Это защищает от сценария, когда сеть подвисла и живой аккаунт
ошибочно помечался мёртвым — а потом безвозвратно удалялся.

### 🗄 Архив (мягкое удаление)

Кнопка **«🗑️ УДАЛИТЬ МЁРТВЫЕ»** больше **не удаляет** аккаунты
безвозвратно — она **перемещает их в «🗄 АРХИВ»**:

- Строка остаётся в БД с `deleted_at = now()`
- Пропадает из всех обычных представлений (хранилище, отчёты,
  проверки, автоочистка)
- В любой момент восстанавливается через **«🗄 АРХИВ»** →
  **«♻️ ВОССТАНОВИТЬ»**
- Статус при восстановлении сохраняется: если аккаунт был `dead`,
  после восстановления его можно перепроверить через
  **«🔍 ПРОВЕРКА АККАУНТОВ»** — живые вернутся в `uncleaned`

**Жёсткое удаление** (`db.delete_account()`) остаётся только за
одиночной кнопкой **«🗑️ УДАЛИТЬ»** в карточке аккаунта — там
требуется явное подтверждение, и это осознанное действие над одним
конкретным аккаунтом.

### 📊 Отчёты
- Общий отчёт по хранилищу
- Статистика за 30 дней
- Отчёт по каждому аккаунту (профиль, сессии, чаты, каналы, группы)
- История действий (`actions_log`)
- **Экспорт в CSV** (UTF-8 + BOM, разделитель `;`):
  - Все аккаунты
  - Один аккаунт (все поля + session)
  - Все логи
  - История одного аккаунта
  - LZT-покупки

### 🛒 LZT Market
- Покупка аккаунтов: случайная страна / конкретная страна / оптовая
- Импорт уже купленных лотов
- Повторный вход в неудавшиеся лоты
- Статистика покупок: вошёл / без входа / провалился / потрачено

### 💾 Бэкапы и восстановление

- Автоматический бэкап после каждого изменения (`accounts_backup.json`)
- JSON в читаемом виде — можно посмотреть глазами
- Восстановление из бэкапа при старте (если БД пуста)
- Архивные аккаунты в бэкап **не попадают** (мягкое удаление = запись
  исчезает из `accounts_backup.json`, но остаётся в БД с `deleted_at`);
  при восстановлении аккаунт снова попадает и в бэкап

**Стратегии удаления:**

| Действие | Что происходит | Восстановление |
|---|---|---|
| **🗄 В АРХИВ** (кнопка «🗑️ УДАЛИТЬ МЁРТВЫЕ») | `deleted_at = now()`; из обычных видов и бэкапа пропадает | «🗄 АРХИВ» → «♻️ ВОССТАНОВИТЬ» |
| **🗑️ УДАЛИТЬ** (в карточке одного аккаунта) | Жёсткое: строка удалена из БД и из бэкапа | ❌ невозможно |
| `db.delete_account_soft()` (только из кода) | Удаляет только из БД, бэкап не трогает | При следующем старте восстановится из бэкапа |
